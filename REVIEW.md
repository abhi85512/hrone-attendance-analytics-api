# REVIEW.md

Defects found in the starter `app/main.py` (helpers and endpoints):

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `list_employees` | Pagination offset calculation used `skip = page * page_size`. For page 1, this skipped `1 * page_size` items, missing the entire first page. | Calling `GET /employees?page=1&page_size=10` returned items starting from index 11 rather than index 1. | Corrected offset formula to `skip = (page - 1) * page_size`. |
| 2 | `list_employees` | Total count query `db.employees.count_documents({})` ignored the filter query `q`. | Calling `GET /employees?department=Engineering` returned filtered items but reported the unfiltered total count of all employees in the entire company. | Changed to `db.employees.count_documents(q)`. |
| 3 | `list_attendance` | In-memory sorting and pagination: called `list(db.attendance_logs.find(q))` loading all matching records into RAM, followed by Python `.sort()` and slice. | Severe latency and OOM danger on large collections (e.g. 100k+ logs); does not use MongoDB indexes. | Replaced with cursor-level `.sort([("date", -1), ("emp_code", 1)]).skip(skip).limit(page_size)` backed by compound index. |
| 4 | `punch_in` | `datetime.fromtimestamp(body.punched_at / 1000)` created naive local datetime and did not truncate sub-second precision. | Stored timestamp had local machine offset and sub-second microseconds, violating business rule R1 (truncate to seconds) and causing inconsistent UTC comparisons. | Converted via `datetime.fromtimestamp(body.punched_at // 1000, tz=timezone.utc).replace(microsecond=0)`. |
| 5 | `punch_in` | Direct dictionary lookup `emp["shift_start"]` without verifying if employee was found (`emp is None`). | Passing a non-existent `emp_code` raised an unhandled `TypeError` (HTTP 500 crash) instead of a clean HTTP 404 client error. | Added explicit check `if not emp: raise HTTPException(status_code=404, detail="Employee not found")`. |
| 6 | `compute_late_minutes` | Replaced `hour` and `minute` directly on UTC datetime without converting to the employee's business timezone (Asia/Kolkata / IST UTC+05:30). | For a 09:00 IST shift (03:30 UTC), a punch-in at 09:05 IST (03:35 UTC) was compared against 09:00 UTC, producing wildly erroneous negative or invalid late durations. | Converted `punch_in` to IST, built shift start on the attendance date in IST, and computed late duration in minutes against that boundary. |
| 7 | `compute_overtime` | Assumed shift end always falls on the same calendar day `date_str`. | For overnight shifts (e.g., 22:00 to 06:00), `shift_end` is on the next calendar day (`date + 1 day`). Comparing same-day timestamps generated massive negative or incorrect overtime. | Detected overnight shifts (`shift_end <= shift_start`) and added `timedelta(days=1)` to `shift_end_dt`. |
| 8 | `create_employee` | Used `datetime.now()` creating a timezone-naive datetime for `created_at`. | Naive local datetimes in MongoDB cause ambiguous time offsets across servers and test runners. | Changed to timezone-aware `datetime.now(timezone.utc)`. |
| 9 | `punch_in` | Check-then-act pattern without unique index allowed race conditions. | Concurrent identical punch-in requests both passed the read check and inserted duplicate logs for the same day. | Enforced compound unique index `(emp_code, date)` catching `DuplicateKeyError` (returning 409 Conflict). |
| 10 | `health` | Health endpoint returned hardcoded `{"status": "ok"}` 200 without verifying database connection. | Calling `GET /health` when MongoDB server was unreachable returned 200 OK instead of the required 503 Service Unavailable. | Added `client.admin.command("ping")` inside a try-except block, raising `HTTPException(503, "MongoDB unreachable")` on failure. |
| 11 | `attendance_date_for_punch` | Helper simply converted timestamp to IST calendar date without checking for overnight shifts (`shift_end <= shift_start`). | For an overnight shift (22:00–06:00), a punch-in at 05:30 IST was assigned to the punch day rather than the day the shift started, breaking Rule R1. | Added check: if overnight shift and IST time is strictly earlier than `shift_end`, assign attendance date to previous calendar day (`ist.date() - timedelta(days=1)`). |
| 12 | Pydantic validation | `punched_at` lacked range and type validation, accepting seconds (10 digits), floats, strings, and negative values. | Sending epoch seconds (e.g. `1783312500`) did not trigger validation error, violating OpenAPI contract requiring epoch milliseconds (`100_000_000_000` to `4_102_444_800_000`). | Added Pydantic field validator `_val_epoch` enforcing integer type and valid millisecond bounds with HTTP 422 on failure. |
| 13 | `punch_in` status validation | Punch-in allowed any status string or did not reject non-presence statuses like `ABSENT` or `LEAVE`. | Passing `status: "ABSENT"` or `"LEAVE"` in `/attendance/punch-in` body created invalid punch records with absence statuses. | Added validator on `PunchInIn.status` allowing only `{"PRESENT", "WFH", "ON_DUTY"}` and raising 422 for others. |

### Considered and Decided NOT a Defect:
- **10-minute grace period threshold (`compute_late_minutes`)**: Verified whether punch-in at exactly 10:00 past shift start incurs late penalty. Rule R2 states punches strictly more than 10:00 after shift start are late (`diff_sec > 600`), and late minutes are calculated from shift start using `floor` (`diff_sec // 60`). Punches at exactly 10:00 (e.g. 09:40:00 for a 09:30 shift) receive 0 late minutes, which is working as intended.
- **Overtime minimum 30-minute threshold (`compute_overtime_minutes`)**: Evaluated whether overtime of 15 or 25 minutes should be recorded. Rule R3 specifies overtime is counted only when elapsed time after shift end is at least 30 minutes (`minutes >= 30`); otherwise 0. Confirmed correct.
- **Half-day threshold at `< 4.50` hours**: Rule R5 specifies that `half_day` is true when rounded work hours `< 4.50`. Work hours of exactly 4.50 hours count as a full day (`half_day = False`). Confirmed correct.
- **Decimal Round Half-Up (`ROUND_HALF_UP`)**: Standard Python `round()` uses round-to-even (banker's rounding). Decimal `ROUND_HALF_UP` was verified as explicitly required by R4 and R8 for work hours and rates. Retained.
- **Canonical Date string format (`YYYY-MM-DD`)**: Keeping `date` as an ISO string in addition to BSON datetimes was confirmed per `DATA_MODEL.md` to avoid unnecessary time zone conversions.
